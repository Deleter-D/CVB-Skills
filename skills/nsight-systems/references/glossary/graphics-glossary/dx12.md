# Direct3D 12 (DX12)

**Short:** Microsoft's low-level explicit graphics and compute API for Windows; the application owns resource state, command recording, queue submission, and CPU / GPU synchronization, with the driver doing minimal validation at submit time.

**Details:**

- The submission model splits work into typed command queues (Direct, Compute, Copy) and command lists. The application records lists on one or more CPU threads and submits with ``ID3D12CommandQueue::ExecuteCommandLists``.
- A Pipeline State Object (PSO) bakes shaders plus blend, depth, rasterizer, and input layout state into one compiled object; switching PSOs is cheap once they exist, which is why renderers create PSO pools up front.
- Resources live in heaps; descriptors (SRV, UAV, CBV, RTV, DSV, sampler) live in descriptor heaps and are bound through a Root Signature that the PSO declares.
- Resource state transitions and barriers (``ResourceBarrier``, enhanced barriers) are the caller's responsibility; the driver no longer tracks state implicitly.
- Synchronization is via ``ID3D12Fence`` (timeline-style values), with ``Signal`` and ``Wait`` on queues. Cross-queue ordering is expressed by signaling on one queue and waiting on another.
